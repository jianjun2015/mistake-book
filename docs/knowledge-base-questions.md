# 本地知识库 - 疑问清单

> 夜间自主开发中遇到的疑问，已按最佳方案执行，白天确认后可调整。

## 1. 技术选型相关

### Q1: Embedding模型选择
- **当前选择**: `shibing624/text2vec-base-chinese`（轻量级，约400MB，768维）
- **备选方案**: `BAAI/bge-m3`（更精准，约2GB，1024维）
- **疑问**: 服务器内存有限，是否需要更高精度的模型？如果对检索精度要求高，可考虑：
  - a) 升级到bge-m3（需要更多内存）
  - b) 使用API调用云端Embedding（如智谱、通义）
  - c) 保持text2vec（当前方案）

### Q2: 元数据库选择
- **当前选择**: SQLite（轻量、无需额外服务）
- **备选方案**: 复用现有MySQL（已运行中）
- **疑问**: 是否需要与错题本主系统共享用户/权限数据？如果需要，应改用MySQL。

### Q3: 图片OCR方案
- **当前选择**: Tesseract（轻量，安装简单，中文识别一般）
- **备选方案**: PaddleOCR（识别效果好，但需要PaddlePaddle框架约1GB+）
- **疑问**: 图片OCR的中文识别精度要求高吗？如果需要高精度，建议安装PaddleOCR。

### Q4: 语音转文字方案
- **当前选择**: OpenAI Whisper（本地运行，需要约1-2GB内存）
- **备选方案**: 腾讯云语音识别API（云端处理，按量付费）
- **疑问**: 
  - a) 是否需要语音/视频转文字功能？（当前是预留接口）
  - b) 如果需要，本地Whisper还是云端API？（本地免费但耗资源，云端稳定但收费）

## 2. 功能需求相关

### Q5: 用户权限
- **当前选择**: 单用户模式（不区分用户，所有人共享知识库）
- **疑问**: 是否需要多用户隔离？每个孩子/学生只能看到自己的知识库？

### Q6: 知识库与错题本关联
- **当前选择**: 独立模块，不与错题本关联
- **疑问**: 是否需要：
  - a) 错题关联到知识库文档？
  - b) 从错题自动生成知识卡片？
  - c) 学习资料智能推荐？

### Q7: 文档大小限制
- **当前选择**: 单文件最大50MB
- **疑问**: 是否需要更大的文件支持？大文件处理会比较慢。

### Q8: 知识图谱功能
- **当前选择**: 暂未实现（复杂度高）
- **疑问**: 是否需要知识图谱可视化功能？（实体关系抽取、图谱展示）

## 3. 部署相关

### Q9: 访问方式
- **当前选择**: 独立FastAPI服务（端口8001），Nginx反向代理
- **疑问**: 
  - a) 是否需要独立域名（如 kb.ty66666.cloud）？
  - b) 还是集成到错题本的路径下（如 ty66666.cloud/kb/）？

### Q10: 数据备份
- **当前选择**: 无自动备份
- **疑问**: 知识库数据是否需要定期备份？建议：
  - a) 每日自动备份到本地
  - b) 备份到对象存储（COS）
  - c) 不需要备份

## 4. LLM相关

### Q11: RAG回答质量
- **当前选择**: MiMo v2.6 Pro，固定提示词模板
- **疑问**: 
  - a) 是否需要调整回答风格（如更口语化/更正式）？
  - b) 是否需要支持多轮追问？
  - c) 回答长度限制？（当前约1500 token）

## 已决策事项（夜间自主决定）

| 决策 | 方案 | 理由 |
|------|------|------|
| 向量数据库 | ChromaDB | 轻量、无需额外服务、本地持久化 |
| 文本分块 | 段落优先，500字/块，50字重叠 | 平衡检索精度和上下文连贯 |
| 搜索方案 | 混合搜索（语义+关键词，RRF融合） | 兼顾精确匹配和语义理解 |
| 文件存储 | 本地文件系统 ./data/uploads | 简单可靠，服务器磁盘充足 |
| API风格 | RESTful + FastAPI | 异步高性能，自动API文档 |
| 前端集成 | 集成到错题本前端 | 统一入口，复用认证 |
| 部署方式 | 独立FastAPI服务 | 解耦、易维护 |

**优先级建议：**
- 🔴 高：Q2（用户权限）、Q5（多用户）、Q9（访问方式）
- 🟡 中：Q1（Embedding精度）、Q3（OCR质量）、Q6（错题关联）
- 🟢 低：Q4（语音）、Q7（文件大小）、Q8（知识图谱）、Q10（备份）
